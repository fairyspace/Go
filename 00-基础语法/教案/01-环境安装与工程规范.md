## 1. 教学目标

### 1.1 知识目标
1. 能说出 Go 的三个设计取向：编译型 + 静态类型 + 内置并发。
2. 能解释 `GOROOT` / `GOPATH` / `GOBIN` 各自的作用，以及为什么现代 Go 不再需要手动设置 `GOROOT`。
3. 能说出 `go.mod` 与 `go.sum` 的区别，以及两者都必须提交版本库。

### 1.2 能力目标
1. 独立完成 Go 安装并用 `go version`、`go env` 验证。
2. 用 Go Modules 从零初始化一个项目（`go mod init` → `go mod tidy` → `go build ./...`）。
3. 按 `cmd/ internal/ pkg/` 规划一个中型项目目录。

### 1.3 素养目标
1. 建立"**先跑通工具链，再写业务**"的习惯：任何环境问题都要能用 `go env` 定位。
2. 建立"**编译产物不入库**"的仓库卫生意识（本次审阅发现仓库里躺着 2.3 MB 的 `.exe`）。

## 2. 重点与难点

| | 内容 | 处理方式 |
|---|---|---|
| **重点** | Go Modules 工作流；`go build` / `go run` / `go install` 的产物位置差异 | 现场演示 + 让学员用 `ls` 亲眼看到产物 |
| **难点** | GOPATH 时代的心智残留（网上大量 2019 年前的教程仍要求把代码放进 `$GOPATH/src`） | 用一段"旧教程 vs 现代做法"对照表集中破除 |
| **难点** | `internal/` 的编译器强制约束（不是约定，是语言规则） | 现场制造一次跨包引用错误 |

## 3. 课前准备

**教师**：投影 + 本机 Go 1.24 以上；准备一个"故意装错"的终端会话（`GOROOT` 乱设导致 `go: cannot find GOROOT`）。
**学员**：笔记本，课前完成 Go 下载安装（下发安装包，避免课上占带宽）。

**版本基线（重要）**：本教案以 **Go 1.27.1** 为基准（2026-09-01 发布的稳定版）。仓库现有 `codes/教学/go.mod` 声明 `go 1.22`，建议提升至 `go 1.24` 以上——理由见 §8 勘误 B10。

## 5. 讲授要点（含板书）

### 5.1 板书一：工具链全景

```
源码 .go  ──go build──▶  可执行文件（当前目录）
          ──go run────▶  编译到临时目录并立即执行（不留产物）
          ──go install▶  可执行文件放进 $GOBIN（默认 $GOPATH/bin）
          ──go test───▶  编译 _test.go 并运行
          ──go vet────▶  静态检查（go test 默认会跑）
```

**三个环境变量**

| 变量 | 作用 | 现在还要设吗 |
|---|---|---|
| `GOROOT` | Go 安装根目录 | **不要**。工具链自行推断；手动设错反而报 `go: cannot find GOROOT` |
| `GOPATH` | 默认 `$HOME/go`；存放模块缓存 `pkg/mod` 与 `go install` 产物 `bin` | 用默认值即可 |
| `GOBIN` | 覆盖 `go install` 的落地目录 | 需要时才设 |
| `PATH` | 让 `go` 全局可用 | **必须** |

> 破除旧教程：Go 1.16 起模块模式默认开启，**项目不需要放在 `$GOPATH/src` 下**，可以放任何目录。

### 5.2 板书二：Go Modules 五步

```bash
mkdir myproject && cd myproject
go mod init example.com/myproject   # 1. 生成 go.mod
go get github.com/gin-gonic/gin     # 2. 加依赖（写进 go.mod + go.sum）
go mod tidy                         # 3. 补缺失、删多余
go build ./...                      # 4. 全量编译
git add go.mod go.sum               # 5. 两个都要提交
```

`go.mod` 是**依赖清单**（人要读），`go.sum` 是**校验和**（防投毒，机器读）。二者缺一，别人就装不出同样的依赖树。

### 5.3 板书三：项目目录

```
myproject/
├── cmd/server/main.go      # 入口：只做装配（读配置、连依赖、启动）
├── internal/               # 编译器禁止外部项目 import
│   ├── handler/  service/  repository/
├── pkg/md5/                # 明确要给外部用的才放这里
├── configs/  scripts/  docs/
├── go.mod  go.sum  Makefile
└── .gitignore              # 必须忽略 *.exe *.test *.out
```

**三条铁律**
1. `main` 包不写业务逻辑——它只负责把依赖装配起来。
2. 业务代码默认放 `internal/`；`internal/` 是**语言级约束**，外部项目 import 会编译报错，不是靠自觉。
3. 编译产物、`vendor/`（除非明确需要）不入库。

### 5.4 小结（口述五句）
1. `go version` 验证安装，`go env` 排查环境。
2. `GOROOT` 别手动设。
3. `go build` 产物在当前目录，`go install` 产物在 `$GOBIN`，`go run` 不留产物。
4. `go.mod` + `go.sum` 必须提交。
5. `cmd/` 装配、`internal/` 业务、`pkg/` 对外。

## 6. 演示脚本（live coding）

```bash
# 1. 验证
go version          # go version go1.27.1 linux/amd64
go env GOROOT GOPATH GOBIN

# 2. 初始化 + Hello World
mkdir -p demo && cd demo
go mod init example.com/demo
cat > main.go <<'EOF'
package main

import "fmt"

func main() {
	fmt.Println("Hello World!")
}
EOF
gofmt -l .          # 无输出 = 格式正确
go vet ./...        # 无输出 = 无可疑代码
go run .            # Hello World!
go build -o demo .  # 产物：./demo
ls -lh demo
```

> 对应仓库示例：`../codes/教学/s01_hello/main.go`（`go run ./s01_hello`）。

## 7. 课堂练习（含参考答案）

**练习 1（基础）** 写出下列命令的产物落地位置：`go build ./cmd/server`、`go install ./cmd/server`、`go run ./cmd/server`。
> **答**：当前目录生成 `server`（Windows 为 `server.exe`）；`$GOBIN`（默认 `$GOPATH/bin`）生成 `server`；不落地产物，直接执行。

**练习 2（基础）** 你的同事 clone 代码后 `go build` 报 `missing go.sum entry`，他该执行什么命令？为什么不能手工编辑 `go.sum`？
> **答**：`go mod tidy`（或 `go mod download`）。`go.sum` 是模块内容的哈希校验记录，手工编辑会破坏防投毒校验，且格式错误会直接构建失败。

**练习 3（进阶）** 把 `internal/service/user.go` 里的 `package service` 改成 `package svc`，`go build ./...` 会报什么？再说明为什么外部项目 import `myproject/internal/service` 会失败。
> **答**：包名与目录名不一致本身**合法**（Go 允许），但所有 import 它的文件必须写 `svc "myproject/internal/service"` 或用 `svc.XXX` 调用；若调用处仍写 `service.XXX` 则报 `undefined: service`。外部项目 import `internal/` 下的包会得到编译错误 `use of internal package ... not allowed`——这是编译器强制的。

## 8. 勘误与易错预警

| 编号 | 学员常见错误 | 教师话术 |
|---|---|---|
| **B10** | 按 2019 年前的教程把代码放进 `$GOPATH/src` 并设 `GOROOT` | 「那是 GOPATH 时代。Go 1.16 起模块模式默认开启，目录随便放。当前稳定版是 1.27.1，你手上的教程如果是 1.12 的，先怀疑教程。」 |
| **B12** | 相信"我这份示例代码肯定能编译" | 「任何'可编译'的断言都要有证据：跑一遍 `go vet ./... && go build ./...`。本仓库目前没有 CI，所以这句话现在是**待证实**的。」 |
| — | 把 `go get` 当成 `npm install` 全量安装 | 「`go get` 是加/升级单个依赖；把 `go.mod` 里声明的依赖全部拉到本地是 `go mod download`。」 |
| — | 忘记 `.gitignore` 里的 `*.exe` | 指着本仓库 `codes/教学/s17_escape.exe`（2.3 MB）说：「这就是忘记忽略的代价——它永久留在 Git 历史里。」 |

## 9. 课后作业（分层）

- **基础（必做）**：在本机建一个 `hello` 模块，写 `main.go` 打印自己的名字；提交 `go.mod`、`go.sum`、`main.go`，并附 `.gitignore`。
- **进阶**：搭出 `cmd/server` + `internal/handler` + `pkg/md5` 三层骨架，`pkg/md5` 提供 `func MD5(s string) string`，在 `cmd/server` 里调用并打印。
- **挑战**：写一个 `Makefile`，包含 `fmt`、`vet`、`build`、`test` 四个目标；要求 `make fmt` 能自动修复格式（提示：`gofmt -w` 或 `go fix`）。
