## 3. 试题库（样例，含参考答案）

### 3.1 概念题（每题 5 分）

**Q1**（02，勘误 A1）`fmt.Printf("%d", 30)` 会输出什么？为什么？`fmt.Printf("%s", 30)` 呢？
> **答**：前者输出 `30`——`%d` 接受任意整型，字面量当然可以直接传。后者输出 `%!s(int=30)`，因为动词 `s` 与实参类型 `int` 不匹配；`Printf` 形参是 `...any`，编译期查不出来，只能运行期报错。

**Q2**（02，勘误 A2）`const x int` 能编译吗？`var x int` 呢？
> **答**：常量必须初始化，`const x int` 编译报错 `missing init expr`；`var x int` 合法，`x` 取零值 0。**零值是变量的机制，常量没有零值一说。**

**Q3**（03，勘误 A12）`map[[]int]string{}` 能编译吗？`map[any]string{}` 呢？后者有什么风险？
> **答**：前者编译不过——key 必须可比较，切片不可比较。后者能编译，但放入不可比较的动态类型（如 `[]int`）时，`m[k] = v` 会在运行时 panic。

**Q4**（08，勘误 A6）goroutine 是线程吗？Go 支持并行吗？
> **答**：不是。goroutine 是 Go 运行时调度的用户态执行单元（GMP 里的 G），初始栈 2KB，由少量 OS 线程承载。Go **既并发也并行**：`GOMAXPROCS` 默认等于 CPU 核数，多核上多个 goroutine 真并行执行。

**Q5**（08，勘误 A7）把 `sync.WaitGroup` 按值传给 goroutine，运行时会发生什么？
> **答**：**不会 panic**。副本有独立计数器，`Done()` 减的是副本，原计数器永不归零，`wg.Wait()` 永久阻塞。`go vet` 会静态报 `passes lock by value`。

**Q6**（09，勘误 A8）循环里的 `s += "golang"` 会被编译器优化成 `strings.Builder` 吗？
> **答**：不会。编译器只折叠**同一条表达式内**的 `a+b+c`（一次 `runtime.concatstrings`）；跨迭代累加仍是每轮分配 + 复制，O(n²)。

### 3.2 输出预测题（每题 8 分）

**Q7**（06）
```go
func calc(index string, a, b int) int {
	ret := a + b
	fmt.Println(index, a, b, ret)
	return ret
}
func main() {
	x, y := 1, 2
	defer calc("A", x, calc("B", x, y))
	x = 3
	defer calc("C", x, calc("D", x, y))
	y = 4
}
```
> **答**：
> ```text
> B 1 2 3
> D 3 2 5
> C 3 5 8
> A 1 3 4
> ```
> 考点：defer 参数**立即求值**（B、D 先打印）；登记的是**值**，后续 `x=3`/`y=4` 影响不到 A、C；defer 按 LIFO 执行。

**Q8**（06）
```go
func t1() int     { a := 1; defer func() { a++ }(); return a }
func t2() (a int) { defer func() { a++ }(); return 1 }
func t3() (b int) { a := 1; defer func() { a++ }(); return 1 }
```
> **答**：`t1 = 1`、`t2 = 2`、`t3 = 1`。只有**命名返回值**能被 defer 修改；`return` 展开为"赋值 → 执行 defer → 真正返回"三步。

**Q9**（03）
```go
s := make([]int, 3, 10)
s[0], s[1], s[2] = 1, 2, 3
sub := s[1:3]
sub = append(sub, 99)
fmt.Println(s, sub)
```
> **答**：`[1 2 3 99 0 0 0 0 0 0]` 与 `[2 3 99]`。`sub` 的 cap = 10-1 = 9，append 未扩容，直接写入 `s[3]`。

**Q10**（04，勘误 A4）`json.Unmarshal` 把 `{"id":1759482245000000}` 解到 `map[string]any`，`m["id"]` 打印成 `1.759482245e+15`。这是否意味着精度丢失？
> **答**：**不是**。该值 < `2^53 = 9007199254740992`，能被 float64 精确表示；`1.759482245e+15` 只是 `%v` 对 ≥7 位有效数字的**显示方式**。真正丢精度需要 > 2^53（例如 `9007199254740993` 或 19 位雪花 ID）。

### 3.3 找错题（每题 10 分）

**Q11** 指出所有问题并修正：
```go
func readAll(paths []string) error {
	for _, p := range paths {
		f, err := os.Open(p)
		if err != nil {
			return err
		}
		defer f.Close()
		process(f)
	}
	return nil
}
```
> **答**：① 循环内 defer——所有句柄到函数结束才关闭，路径多时耗尽文件描述符；② 无法区分"哪个文件失败"。修正：
> ```go
> for _, p := range paths {
> 	if err := readOne(p); err != nil {
> 		return fmt.Errorf("读取 %s 失败: %w", p, err)
> 	}
> }
> func readOne(p string) error {
> 	f, err := os.Open(p)
> 	if err != nil { return err }
> 	defer f.Close()
> 	return process(f)
> }
> ```

**Q12** 指出问题：
```go
var counter map[string]int
func hit(k string) { counter[k]++ }

func tryAppend(s []int) { s = append(s, 1, 2, 3) }
```
> **答**：① `counter` 是 nil map，写入 panic（`assignment to entry in nil map`）——改为 `make(map[string]int)`；② `tryAppend` 扩容后调用方看不到新长度——应返回新切片：`func tryAppend(s []int) []int { return append(s, 1, 2, 3) }`。

**Q13** 指出问题：
```go
var wg sync.WaitGroup
for _, u := range users {
	go func() {
		wg.Add(1)
		defer wg.Done()
		fetch(u)
	}()
}
wg.Wait()
```
> **答**：三处：① `Add` 在 goroutine 内部，`Wait()` 可能在 `Add` 前就返回；② Go ≤1.21 时 `u` 被所有闭包共享；③ `fetch` 若 panic 会崩掉整个进程。修正：`wg.Add(1)` 移到 `go` 之前（或 `wg.Add(len(users))` 一次加完）、goroutine 显式接收 `u`（Go 1.22 前的写法）、入口加 `recover`。

### 3.4 编码题（每题 15 分）

**Q14** 实现 `func GroupBy[T any, K comparable](items []T, key func(T) K) map[K][]T`（要求用到泛型与 `comparable` 约束）。
> **参考**：
> ```go
> func GroupBy[T any, K comparable](items []T, key func(T) K) map[K][]T {
> 	out := make(map[K][]T, len(items))
> 	for _, it := range items {
> 		k := key(it)
> 		out[k] = append(out[k], it)
> 	}
> 	return out
> }
> ```
> 评分点：约束写对、预分配容量提示、nil 输入不 panic、有单测。

**Q15** 实现限流并发抓取（并发度 ≤ N、结果按入参顺序、任一 panic 不影响整体）。参考 08 篇练习 3 的答案。
> 评分点：信号量控制并发、按下标写入预分配切片（无锁）、`defer wg.Done()`、`recover`、`-race` 无警告。

## 4. 综合项目（30%）

**题目**：实现一个**第三方接口聚合服务**（命令行工具即可，不要求 HTTP）。

**功能要求**
1. 读取配置文件（`json`），包含若干数据源（可用本地 JSON 文件模拟接口响应）。
2. **并发**拉取所有数据源，并发度可配置，单个源超时 2s。
3. 任一源失败不影响其他；全部结束后汇总成功/失败列表。
4. 结果按 struct 解析（**禁止用 `map[string]any` 接 ID/金额**），输出为格式化 JSON。
5. 关键路径打日志（`log/slog`），错误链完整（`%w` + `errors.Is`）。

**工程要求**
- 目录遵循 `cmd/ internal/ pkg/`；
- `gofmt -l .`、`go vet ./...`、`go test ./...`、`go test -race ./...` 全部干净；
- 至少 5 个单测，覆盖：配置缺失、超时、部分失败、ID 为 19 位整数；
- 至少 1 个基准测试，并写 200 字"性能观察记录"。

**答辩问题（每人 3 问）**
1. 你的并发度是怎么定的？调大调小分别观察到什么？
2. 如果去掉 `close(jobs)`，程序会怎样？为什么？
3. 你有没有用上 `sync.Pool`？为什么用/不用？（**期待答案：不用，并用 `allocs/op` 说明它不是热点**——勘误 A16）

## 5. 常见失分点（教师参考）

| 失分点 | 对应篇目 | 说明 |
|---|---|---|
| 用 `time.Sleep` 等 goroutine | 08 | 直接判"并发不正确" |
| 循环内 `defer` | 06 | 资源泄漏类问题一律重扣 |
| 用 `map[string]any` 接 ID | 04 | 数据正确性风险，重扣 |
| 循环里 `s += ...` | 09 | 性能类，要求给出基准对比 |
| 没有 `_test.go` | 06 起 | 该次作业不计分 |
| 错误用字符串比较 | 10 | `errors.Is` 是硬性要求 |
| 提交 `*.exe` / 未写 `.gitignore` | 01 | 仓库卫生，扣分并当堂演示后果 |
