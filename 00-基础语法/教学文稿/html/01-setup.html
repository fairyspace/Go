01 环境安装与项目结构

学完本篇你将能够：在本机装好 Go、写出第一个程序、说清 GOPATH 与 Go Modules 的区别、独立完成项目目录规划。

你好，Go 语言

Go 是一个开源的编程语言，它能让构造简单、可靠且高效的软件变得容易。

环境安装

目标：安装完成并运行 Hello World 成功！

方式一：包管理器

BASH

# Windows (PowerShell)
winget install GoLang.Go

# Ubuntu
sudo apt install golang-go

方式二：官方安装包

下载地址：https://go.dev/dl/

验证

BASH
go version
# go version go1.22.5 windows/amd64

环境变量

变量作用是否必需
GOROOTGo 语言安装根目录现代 Go 已自动推断，无需设置
GOPATH工作区路径，用于存放依赖缓存建议保留默认值 $HOME/go
PATH让 go 命令全局可用必需
BASH
# macOS / Linux —— 旧版本才需要手动设置 GOROOT
export GOROOT=/usr/local/go
export GOPATH=$HOME/go
export PATH=$PATH:$GOROOT/bin:$GOPATH/bin
POWERSHELL
# Windows PowerShell
[Environment]::SetEnvironmentVariable("GOROOT", "C:\Go", "User")
[Environment]::SetEnvironmentVariable("GOPATH", "$env:USERPROFILE\go", "User")

修改后需重开终端生效。

重要更新（原文基于 Go 1.12，以下为现代 Go 1.20+ 做法）

  1. GOROOT 不再需要手动设置。
  2. Go 1.16 起 模块模式默认开启；Go 1.22 起 go build 也不要求项目位于 $GOPATH/src 下。
  3. 现在的标准做法是 Go Modules，见下节。

Go Modules：现在的项目初始化方式

BASH
mkdir myproject && cd myproject
go mod init example.com/myproject   # 生成 go.mod
go get github.com/gin-gonic/gin    # 下载依赖，自动写进 go.mod
go mod tidy                        # 清理无用依赖、补全缺失
go build ./...

生成的 go.mod：

代码片段
module example.com/myproject

go 1.22

require github.com/gin-gonic/gin v1.10.0

go.mod（依赖清单）、go.sum（校验和）需要 提交到 Git 版本库。

常用 module 命令

命令作用
go mod init <模块名>初始化模块
go mod tidy添加缺失依赖、移除无用依赖
go mod download下载全部依赖到本地缓存
go mod vendor把依赖复制到 vendor/ 目录
go list -m all列出当前模块的所有依赖及版本

GOPATH 目录结构（了解即可）

代码片段
├─ $GOPATH
│  ├─ bin      编译后可执行文件
│  ├─ pkg      编译后的应用包 + 依赖缓存（module cache）
│  └─ src      应用源代码（Go Modules 时代已不再强制）

BASH
go run ./s01_hello

常用命令

命令作用
go build hello编译，在当前目录生成可执行文件
go install hello编译并把结果移动到 $GOPATH/bin
go run hello.go直接运行，不生成文件
go fmt ./...格式化代码为标准格式
go vet ./...静态检查可疑代码
go test -bench . ./...运行测试与基准测试
go mod tidy整理依赖
go env查看当前 Go 环境配置

go build 与 go install 的差别：

  • go build 把产物放在 当前目录
  • go install 把产物放到 $GOPATH/bin（加入 PATH 后可直接执行）

项目目录规划

一个 Go 项目的典型布局：

代码片段
myproject/
├── cmd/                    # 各个可执行程序的入口
│   └── server/
│       └── main.go
├── internal/               # 仅本项目可用的包
│   ├── handler/            # HTTP 处理函数
│   ├── service/            # 业务逻辑
│   └── repository/         # 数据访问
├── pkg/                    # 可被外部项目引用的包
│   └── md5/
│       └── md5.go
├── configs/                # 配置文件
├── scripts/                # 脚本
├── docs/                   # 文档
├── tests/                  # 集成测试
├── go.mod
├── go.sum
└── Makefile

约定：

  • main 包 只做装配（读取配置、初始化依赖、启动服务），不写业务逻辑
  • 业务代码放 internal/，编译器会阻止外部项目引用
  • 需要对外暴露的才放 pkg/

本篇要点

  1. 现代 Go 用 Go Modules 管理项目，GOROOT 不再手动设置。
  2. go build 产物在当前目录，go install 产物在 $GOPATH/bin。
  3. go.mod 和 go.sum 必须提交版本库。
  4. cmd/ 放入口、internal/ 放业务、pkg/ 放对外接口，main 包不写业务。
  5. 装完 Go 第一件事：go version 验证，然后 go mod init。
